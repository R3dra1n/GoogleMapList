# Preview 6 確認後的發布與登入

## 這次發布範圍

靜態前端、創作者展示頁、搜尋、內容作者歸屬、管理員主題策展。尚未開放公眾自助登入或寫入。

發布前：
1. 使用者確認 Preview 6。
2. 抓取 main 最新 CMS 內容，保留使用者期間新增／修改，不用預覽資料覆蓋新版內容。
3. 版本升為 1.1.0，重新建置；確認移除 preview 禁寫模式後，管理員登入、編輯、媒體上傳與發布可用。不可把目前替換成說明頁的 dist/admin 直接發布。
4. 檢查 GitHub Pages 子路徑、獨立頁的 base/canonical/OG、舊網址、深色模式與五語系。檢查原清單作者欄位與精選開關。
5. GitHub Actions 通過後部署並做正式 URL 冒煙測試。保留 v1.0.0 及前一個成功部署供回復；不回退使用者的新內容。

## 首頁與策展

首頁今日發現由公開可見清單池按固定 key 排序、台北日期每天輪換六份；同一天、同資料集所有訪客一致，不是人氣排名。清單不足六份全部顯示；發布新增或隱藏資料會改變當天結果。不會定時刷新已開啟的頁面，下次造訪／刷新使用當日日期。現階段沒有付費 API 或排程需求。
主題精選使用 themes.curated，管理員在 CMS 勾選，沿用 order 排序。既有七份主題保留精選；新建預設 false。未精選但公開的主題仍在搜尋、作者頁及輪替池。content/site.json 的舊 featured 首頁設定已不作為首頁來源，保留檔案避免破壞歷史資料。
原作者 originalAuthor 與 owner（本站維護者）分離；兩份 Google Maps 歸屬依管理員提供的資訊設定，originalAuthorSource 保留原分享網址，未另行驗證官方帳戶。不要把這個歸屬當成 Google 已入駐或授權的證明。

## 下一階段：受邀創作者登入 MVP

先採邀請制，不將 GitHub 倉庫寫入權限交給一般創作者。沿用 Cloudflare Worker/D1 的可行性需先檢視現有 schema 與方案，不新增付費服務。

- 身分：一般訪客、創作者、管理員。外部登入身分綁定內部 user_id，session 使用安全 cookie。需要選定登入供應商與 OAuth 配置後才實作開放。
- 所有權：user_id → creator_id；每次伺服器寫入都驗證歸屬，不相信前端傳入 owner。來源作者不等於帳號所有者。
- 頁面：姓名、簡介、頭像、Banner、社群連結。限制圖片大小／格式，保留裁切預覽及替代文字，不允許任意 HTML/CSS。
- 清單：草稿 → 提交審核 → 公開／退回／下架。草稿與私人資料不得進公開 data.json 或公開 Git 倉庫。
- 策展：只有管理員可設 curated、排序及下架；創作者不能靠自訂請求變更。
- 驗證：兩個測試帳號交叉讀寫被拒、草稿不外洩、登出與 session 到期、媒體上傳限制、審核紀錄與回復。

登入階段先做資料／權限設計，再接認證和創作者編輯頁，最後小規模邀請測試。這些未包含於 Preview 6，不能把靜態 creators JSON 當成已完成的使用者系統。
